# 软件 I2C 内部上拉版本（2026-10-31）

用户要求“启用上拉看看，改成上拉”后，已修改驱动、编译、烧录并校验当前板。当前 Release HEX 的 SHA256 为 `B36C1C5AF661195FA1A58C676F02516F4B023B0EEE02BE80561FFBFC43C02230`，烧录校验共 33464 字节。板子保持 STOP，未发送运动指令。

## 实现

- `software/Config/board_config.h`：`BOARD_I2C_INTERNAL_PULLUPS=1`，`BOARD_I2C_HALF_PERIOD_US=10`。
- PB6/SCL、PB7/SDA：释放时先将 ODR 写 1，再切换到输入上拉；拉低时将 ODR 写 0，并切换到 2 MHz 开漏输出。STM32F1 输出模式不能同时启用内部弱上拉，故需要动态切换；没有使用推挽高电平。
- I2C 延时标称对应不高于约 50 kHz。实际 SCL 波形没有用示波器测量，GPIO 操作和 ADC 中断会进一步延长时序。
- 首次判断空闲前增加释放等待。每个事务仍有原有 2 ms DWT 超时，磁铁有效性检查、5 ms 编码器过期保护、电流保护及 CAN 运动超时均保留。
- PWM 仍为 24 kHz，ADC/电流环仍为 2 kHz。I2C 只在前台运行，没有在事务期间屏蔽 ADC 中断。

原固件及三个修改前源文件已备份到 `build/board-debug/pre-internal-pullup-20261031/`。之前桌面发布包内附带的旧固件没有自动更新；此版固件入口是 `software/build/Release/gimbal_foc.hex`。

## 验证

编译使用 `-Wall -Wextra -Werror`；现有 C 控制/应用/CAN 测试通过。Python 测试共 100 项，其中 94 项通过，6 项 Tk 视图测试因该测试解释器未安装 Tk 而跳过。外部上拉配置 `BOARD_I2C_INTERNAL_PULLUPS=0` 也单独编译通过。

烧录后，编码器由 BUS_ERROR 恢复为 `BOARD_ENCODER_OK`，`sensor_valid=true`。随后约 12555 ms 内的 100 次停机快照均为 OK/有效，角度时间戳持续推进；ADC 计数测得约 1999.92 Hz，ADC pending/overrun、Board/App fault 均为 0。电机始终 STOP、driver disabled、EN 低。这不等于逐次 I2C 读取零失败的统计，也未验证带载或高转速工况。

另用不暂停 CPU 的 SWD 轮询观察角度提交时间戳：600 次读取得到 449 次观察到的新提交。相邻新时间戳间隔最小 2618 us、中位 2630 us、95 分位 2860 us；中位对应约 380 Hz。SWD 轮询可能漏掉提交，数值描述观察到的时间戳间隔，不是精确总线频率或传感器内部采样频率。

## 对轮足使用的含义

当前速度适合确认芯片、磁铁及软件上拉是否可用，以及低速调试。正式轮足控制应结合最大转速、11 极对及动态负载验证角度延迟；2 kHz 电流 PI 仍执行，但不能把其运行频率等同于新角度更新频率。现有速度外推也不能证明高动态下相位误差可忽略。

按当前读取流程，一次状态及双字节角度读取共需约 81 个 SCL 时钟；50 kHz 时仅这些位传输就约 1.62 ms，尚未计入其他开销。建议修复外部上拉链路后提高通信速率，以本板配置的约 1 kHz 角度更新为验证目标，并继续做带载动态验证。AS5600 数据手册支持最高 1 MHz I2C，但能否达到目标速率还需验证 PCB 的上升时间及软件执行时序。
