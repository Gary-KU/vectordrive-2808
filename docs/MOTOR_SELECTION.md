# 选择 2808 或 4015 电机

当前支持两种编译配置，默认使用当前接入的 2808。型号与极对数在 `software/Config/motor_profile.h` 统一维护，不再通过修改一处公共极对数覆盖另一台电机。

| `-Motor` | 电机 | 极对数 | Release 固件 |
| --- | --- | ---: | --- |
| `2808` | 当前 2808 | 7 | `software/build/Release/gimbal_foc_2808.hex` |
| `4015` | 原 4015 | 11 | `software/build/Release/gimbal_foc_4015.hex` |

2808 的正反开环实测：±10 电角 rad/s 时，稳定机械速度分别约 +1.429 / −1.445 rad/s，估算 7.00 / 6.92 极对，符合用户确认的 7 极对。4015 保留原先用户确认的 11 极对。这两个档位针对本项目使用的两台电机；同一尺寸型号的其他厂商电机仍需核实实际极对数。

## GCC

在项目根目录执行：

```powershell
# 当前 2808，7 极对
.\build.ps1 -Configuration Release -Motor 2808 -Test

# 原 4015，11 极对
.\build.ps1 -Configuration Release -Motor 4015 -Test
```

原来的 `-Configuration`、`-Toolchain` 和 `-Test` 用法保持有效；所有构建配置都可搭配 `-Motor`。直接运行 `software/build.ps1` 也接受同名选项。

每次编译会生成当前型号对应的 `.hex`、`.bin`、`.elf` 和 `.json`，例如 `gimbal_foc_2808.json` 记录型号、实际编译的极对数、构建配置和 HEX SHA256。另一型号带名称的产物会保留；通用的 `gimbal_foc.hex/elf/bin` 则始终是最近一次构建的型号。烧录时优先选择带型号的 HEX，调试时使用同型号 ELF。

## Keil

工程的 Config 分组已包含 `motor_profile.h`。在目标的 C/C++ → Define 中填写 `MOTOR_MODEL=2808` 或 `MOTOR_MODEL=4015`；未指定时默认为 2808。GCC 和 Keil 共用同一配置头。其他型号会触发编译错误，避免静默采用错误极对数。

本轮已实际编译并测试两个 GCC Release；Keil 工程已同步文件并校验 XML，本轮没有执行 ARMCC 编译。

## 换电机后的操作

先 STOP 并确认驱动关闭，再烧录对应型号固件。若 Flash 中保存值的电机型号/极对数与新固件不匹配，固件保持 STOP 并禁止闭环，不会自动吸合或误用旧零点；在上位机清除保存值后，完整断电重上电才会按当前固件执行一次自动对齐。首次空载对齐确认正确后显式保存，以后软件复位或上电只重采 ADC 偏置并静默恢复。相线顺序或编码器安装改变时必须清除并重新验证。

这是编译选项，切换型号需要重新烧录。CAN 报文与原有 9 个运行参数保持兼容；极对数不在这 9 项 RAM 调参中。PI、限流和斜坡仍从原参数表调节，两台电机可分别保存调参方案，型号选择不代表已为另一台电机完成 PI 整定。

当前两档仍使用 14 V 母线配置、24 kHz PWM、2 kHz 电流环和 1 kHz 速度环，以及原有过流、采样和 CAN 超时保护。外部上拉修复后，软件 I²C 已恢复 2 µs 半周期，内部弱上拉作为补充保留；此前 10 µs 弱上拉诊断时序不适合本机电流 PI 满负载运行。
