# 上位机角度、断流提示与启动联锁（2026-10-31）

## 现场结果

第一次查看当前上位机窗口时，接口实际为“模拟器（不连接真实电机）”，通道 SIM，角度 0°来自模拟节点。该会话不读取真实板子，因此移动磁铁或拔掉真实 CAN 都不会改变模拟角度、产生真实 CAN 断线错误。

切换为 PCAN / PCAN_USBBUS1 / 1 Mbps / 节点 1 并完成 STOP 握手后，窗口立即显示真实机械角度约 269.63°（4.706 rad），编码器有效，驱动关闭。同期 40 次 SWD 快照均为 `BOARD_ENCODER_OK`、`sensor_valid=true`。该阶段真实 CAN 接收窗口收到状态 567、诊断 566、遥测 566 帧，末帧无 bus-off/error-passive。

用户随后尝试启动，并提供故障截图。`0x01080000` 对应两个锁存位：

| 位 | 含义 |
| --- | --- |
| `0x00080000` | `APP_FAULT_ENCODER`：闭环或对齐期间角度反馈曾无效/超时 |
| `0x01000000` | `APP_FAULT_ESTOP`：急停锁存 |

此组合没有 `APP_FAULT_CAN`。故障会关闭驱动并清除电气零点有效标志；当前角度重新有效也不会自行解除故障。用户截图同时显示未完成电气零点、IQ 命令被 `REQUIRE_STOP` 拒绝，不能用增大 Iq 解决。

故障后的 SWD 40 次快照中编码器均恢复 OK，但应用故障仍为 `0x01080000`。关闭旧上位机后，停机 PCAN 接收窗口收到 1570 帧（状态 524、诊断 523、遥测 523），驱动关闭、编码器有效、角度约 114.13°，板级故障 0、bus-off/error-passive=false。诊断 `tx_loss=true` 为累计发送丢失提示；切换接收程序期间总线上没有持续 ACK，不能将它解释为当前应用 CAN 故障或精确定位焊点。

以上结果证明这些观察窗口内 CAN 可以收发、编码器能够读到角度，不能证明旋转带电情况下不会再次丢角度，也不能单凭此排除间歇接触问题。未捕获最初编码器异常发生时的磁场、I²C 波形，暂不能断言它由磁铁偏移、供电干扰还是时序造成。

故障处理顺序：STOP 并确认执行 → 清除锁存故障 → 等待偏置完成 → 确认方向 → 转子对齐 → 电气零点有效后再启动小电流。若仍提示 `REQUIRE_STOP`，重新发送 STOP 并等执行确认。对齐是运动操作；此轮由助手进行的操作仅为监测、STOP、关闭/重启上位机，没有由助手下发对齐或电流目标。

## 上位机修改

- 停机时也检查状态、诊断各自的新鲜度；任一超过 250 ms 未更新即报告 CAN 反馈中断，注明对应 ID，尝试 STOP 并关闭会话，需用户重新连接。
- 运行时保留原有严格的 50 ms 反馈期限和 MCU 的 100 ms CAN 运动命令期限。丢掉角度页不会被误报为整个 CAN 断开。
- 通信异常时清除排队命令；断开过程中 STOP 未确认不会覆盖最初的通信故障原因。STOP 的执行结果仍单独保留。
- 顶部状态区区分“接口打开”与实际节点反馈正常；状态仍在到达但诊断过期时同样禁用启动/调参。
- 编码器无效、角度页过期分别显示原因；模拟器顶部和角度旁明确注明“角度不来自板子”。
- 故障位显示中文名称，`0x01080000` 显示“编码器反馈异常、急停锁存”。诊断要求 STOP 时，会话指示不再因旧主机状态保持绿色。
- 允许连接已有锁存故障的板子：连接用 STOP 的安全应答语义，ACK 携带的故障位用于显示，而不再导致立即断开。连接不清故障、不启动电机，仍需单独 CLEAR 和有效对齐。

维护入口：`desktop/controller.py`、`desktop/telemetry.py`、`desktop/ui.py`。没有修改固件参数、限值或关闭任何保护。
